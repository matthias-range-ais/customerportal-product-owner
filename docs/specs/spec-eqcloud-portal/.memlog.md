- 2026-09-15 init: topic="Tool coupling the EquipmentCloud customer-portal REST API to remove manual, recurring GUI work for a Product Owner"
- 2026-09-15 direction: Scope covers two phases in one spec: CAP-1 (SoftwareCenter software version/set management, now) and CAP-2 (OpenIssues clustering, later).
- 2026-09-15 capability: CAP-1 — manage SoftwareCenter software versions/sets and assign them to customer equipment (hierarchies) through the tool instead of manual EquipmentCloud GUI clicking.
- 2026-09-15 capability: CAP-2 — find commonalities across OpenIssues (issues + discussions) and bundle them into larger backlog items / roadmap themes. Later phase; mechanics not yet detailed.
- 2026-09-15 constraint: Backend is Node.js (decided).
- 2026-09-15 constraint: Only BasicAuth-secured EquipmentCloud REST API endpoints are in scope; Bearer/OAuth2-secured `_oa` endpoint variants (e.g. `equipmenthub_oa`, `openissues_oa`) are excluded — user directive, not all API surface applies.
- 2026-09-15 constraint: EquipmentCloud credentials must be stored via OS-level secret storage (e.g. Windows Credential Manager); never hardcoded or committed to git.
- 2026-09-15 constraint: Every mutating EquipmentCloud API call (POST/PUT/DELETE) must be shown to the user in full (method, path, payload) and explicitly confirmed before execution — no autonomous writes against the production API.
- 2026-09-15 constraint: Code, identifiers, comments, and commit messages are English; GUI-facing text is German.
- 2026-09-15 non-goal: Not a replacement for the EquipmentCloud portal UI itself — the tool maps concrete recurring processes and gives an overview of work that would otherwise be done manually, not general portal administration.
- 2026-09-15 assumption: Treated this as a single-user (solo operator) tool with no multi-user accounts, roles, or customer-facing access — inferred from the solo-project framing (AGENTS.md: commits go directly to `main`), not explicitly stated as in/out of scope by the user.
- 2026-09-15 assumption: The recurring "every ~3 weeks" manual-clicking pain point refers to the CAP-1 software-assignment workflow specifically — it was the concrete example given.
- 2026-09-15 question: Local database choice (SQLite vs. a more suitable alternative) is not yet decided.
- 2026-09-15 question: Frontend framework is not yet decided (established, modern-design framework wanted; specific choice open).
- 2026-09-15 question: CAP-2 (OpenIssues clustering) mechanics — what counts as a "bundled theme," how issues/discussions are compared for commonality — not yet detailed.
- 2026-09-15 question: SBOM tool/format not yet chosen (Node.js ecosystem, e.g. CycloneDX via `npm sbom` — TBD once `package.json` exists).
